## 3. 不平衡处理：首轮保留原始采样

首轮不做类别过采样或欠采样（此处重采样指训练样本分布，不是音频采样率）。每轮训练音频无放回遍历一次，普通微调和关系保持微调共享同一采样规则。

保留现有标签编码 spoof=0, bona_fide=1，以及分类权重 [0.1,0.9]。整轮两类权重和为22800*0.1=2280，2580*0.9=2322，接近均衡。该计算解释既有加权设置的用途，不等于实际梯度大小一定相等。

不直接叠加1:1采样和上述权重：均衡采样后仍用0.1/0.9会给真实样本约9倍单样本权重。若后续独立测试1:1采样，应同时定义相匹配的分类权重及预算，并将其作为采样方向单独比较。

过采样的代价：若保留全部22800伪造并组成1:1，每轮需45600次样本访问，真实样本平均重复约8.84次；相同epoch不再代表相同训练量。若每轮仍固定25380次访问，则平衡采样会减少伪造覆盖量。欠采样则丢掉大量源域攻击样本。当前已有加权分类处理，所以第一轮无需加入这些混杂。

## 4. 真实语音关系损失的归一化

旧稿“每个非空batch按真实数量单独平均”存在空真实批次问题。原比例随机采样时，空真实批次概率近似 (1-p)^B：B=16约0.180，B=8约0.424，B=4约0.651；这是大数据无放回采样下的近似，不是实际批次日志。

首轮采用固定真实先验归一化：

    L_temporal(B) = sum_{i in B, yi=real} r(xi) / (|B| * p_real)

r(x)为第12层、同音频、中心化逐帧归一化后的帧间关系误差，按T(T-1)个非对角元素平均。该估计在原始均匀采样下的期望等于源域真实样本的平均关系误差。空真实批次关系项为0，不增加辅助真实样本、不重排批次。每轮仍使用全部2580条真实音频。

同时分别记录每真实样本的关系误差、空真实批次比例和优化器步内真实数量。首轮新关系系数 lambda_temporal=1.0，属于在归一化定义下预设的起始配置，不称最优系数，也不用目标域选择。后续若需修改，由源域训练数值/梯度诊断支持，明确记录为新实验。

现有后端的 A/B 跨样本关系损失保持系数0.1。完整目标为：

    L = 0.5*(weighted_CE_A + weighted_CE_B)
        + 0.1*L_existing_head_relation
        + 1.0*L_temporal

普通微调臂最后一项为0，其他项不变。时间帧关系与A/B跨样本关系为不同目标，日志必须用不同字段。

## 5. 显存方案与 batch 选择

初始建议：真实 batch16、有效 batch16、无梯度累积。所有臂使用相同 batch。两个 SSL 的 dropout/masking/layerdrop关闭；任务Transformer仍有梯度，eval模式不等于冻结。卷积特征提取器统一冻结，24个Transformer block参与微调，按模块检查梯度范围。

精度采用 BF16 autocast（已确认硬件支持）；模型主参数与优化器状态FP32，分类/关系矩阵归一化及误差计算FP32。所有臂精度相同。先核验Fairseq算子兼容性，若BF16不能运行，则在正式训练前统一采用FP16并记录GradScaler策略，不能在结果出现后换精度。

教师仅在真实样本上执行到第12层，no_grad，不用全batch24层教师输出；关系矩阵应先形成，教师临时特征再释放。若Fairseq没有真正提前退出，则记录实际执行层数并在显存测量前修正，不把“只取第12层”误说成“只计算12层”。教师与任务模型不堆叠成双路融合，不复制教师优化器状态。

按约300M参数估计：任务模型FP32参数、梯度、Adam两个moment约4.8 GB；完整冻结教师FP32参数约1.2 GB。约6 GB是静态参数/优化器的粗估，不含后端、激活、工作区和CUDA allocator；具体参数量与峰值需实测。约201帧时单个FP32关系矩阵仅约0.16 MB，显存主体是任务模型反向激活，而非关系矩阵。

历史E3报告曾测batch16、AMP、双模型峰值约13.6 GB。该数字来自旧实现与旧测量，不是本方案实测，不保证新实现相同。新方案在真实样本上使用半深度教师，具有节省教师计算的条件。

正式启动前做不保存模型的源域工程自检：两臂初始化损失一致（lambda项初始应接近0）；12层关系梯度能到达可训练前层；教师无梯度；执行若干完整forward/backward/optimizer步骤使Adam状态实际初始化。包含纯真实批次作为关系路径峰值压力测试，记录allocated/reserved和时延。

batch16两臂压力测试若均能在约20 GiB reserved以内运行，保留batch16，留显存余量。若不足，在正式训练前统一选择batch8、有效batch8并重做自检；记录优化器步数变化。初版不以累积伪装成大batch，不暗中改冻结层数。必要时再以独立实现启用Transformer activation checkpointing，所有微调臂一致。

原因：现有A/B关系损失跨batch样本，两个batch8分别计算不是一个batch16的关系矩阵。若未来使用累积，分类weighted CE的分母必须按整个有效batch权重和计算，时间关系项按整个有效batch规模*p计算；跨样本头关系还需要全有效batch的对应实现。不能把microbatch的mean损失直接等权相加当作完全等效。

PyTorch官方依据：[weighted CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)、[activation checkpointing](https://docs.pytorch.org/docs/stable/checkpoint.html)。目标环境torch2.5.1，未来实现时还须核对实际API和Fairseq行为。

## 6. 首轮受控设计

预定工程筛查seed20；之后有希望才扩展1001和7。固定已有 raw-layer 后端（23个layers[1:]输入），保留hidden_dim192、双头与原关系目标。不添加交叉注意力、残差门控、prototype或新增音频增广。

共同冻结XLS-R预热检测头3轮，固定使用第3轮状态作为分支起点。从同一状态分出：

- F：继续冻结XLS-R，后端再训练7轮。
- FT：24层Transformer参与普通微调，后端再训练7轮。
- RP：与FT相同，仅新增真实语音第12层时间关系保持损失，再训练7轮。

总样本暴露为每臂10轮（共同预热共享计算）；任务SSL lr=1e-6，head lr=1e-4，AdamW weight_decay1e-4，梯度裁剪5.0。正式epoch4-10按各臂预注册源域完整训练目标最低值保存权重；各项损失分别记录，warmup候选不混入微调阶段选权重。不比较不同目标定义下train_loss数值大小来判定方法优劣。

预热和FT共同构成同一训练方案；后续若需要与从头联合微调比较，另作训练顺序消融，不将LP-FT已有思路称为本方法新贡献。

### 7.1 每四轮完整评估与提前停止

用户2026-10-07新增要求：每4个epoch完整评估一次，明显很差可中断。采用总epoch编号，第4、第8轮做全部预定跨语域和ITW评估；第10轮训练结束补最终评估。共同预热占epoch1-3，所以epoch4首次评估只包含1轮骨干适配，是早期筛查，不能要求已达最终效果。

各节点评估截至该节点最低源域训练损失权重，报告A/B/固定联合，不根据目标域挑更早epoch或单头。保留所有中期结果和实际停止轮次。中期目标域用于停止决策，明确将整个方案标为探索性、非纯盲测。

首轮按阶段推进：共同预热后，各臂先到epoch4并评估；有必要再到epoch8，最后到epoch10。这样可在早期结果已经明显失败时节约开销。FT与RP需在相同节点比较；恢复时保存优化器状态和必要RNG状态，不将重新初始化优化器冒充连续训练。磁盘不足时须先报告，不删除原有权重。

明显失败的初版停止规则：数值异常/OOM立即停止并记录；或同节点RP至少两个跨语域比FT高5个百分点以上且跨语等权均值高3个百分点以上，允许停止RP。第4轮仅轻微落后或单域取舍不触发该规则。若第8轮仍无跨语收益且ITW比FT差2个百分点以上，亦停止。均保留已运行记录，不将中止当成已完成多种子验证。
